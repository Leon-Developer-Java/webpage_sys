## 数据链路

普通文件和 FY-3/Himawari 集合统一通过 `backend_upload:8003` 分片上传：

```text
浏览器分片上传
  -> backend_upload 写入共享 DB 和私有 raw 存储
  -> backend Adapter Worker 异步解析
  -> backend/data 生成 meta/WebP
  -> backend_upload 目录接口选择资源
  -> backend:8002 提供展示响应和 /data 文件
```

上传成功只表示文件已入队。前端继续轮询 `pending/running/success/failed`，不再把同一文件二次提交给 8002。FY-3/Himawari 在上传前调用集合准备接口，由服务端判断 science/geo、波段和分段完整性。

## WRF 共用组件发布与验证

`wrf-ui.lock.json` 绑定版本、源码 SHA-256、JS bundle SHA-256、npm tarball integrity 和构建工具版本。`node scripts/build-wrf-ui.mjs` 重建并校验锁；只有维护发布时才使用 `--update-lock`。主站和 AgentScope 前端通过各自锁文件安装同一个 `.artifacts/wrf-ui/<version>/*.tgz`，无需私有 registry。部署版本不可覆盖成不同内容；源代码或打包内容变化时更新包版本并同时更新两端锁。构建前的 `verify-wrf-ui.mjs` 核对主站实际安装 bundle 和锁，防止 file 依赖旧缓存冒充新包。React 宿主对该已编译包关闭 Vite 再优化。

更新包后，长期运行的 Vite 开发服务可能保留 node_modules 的旧模块转换及 immutable URL。应核对实际服务脚本的版本，按进程身份仅温和刷新对应前端，再完整刷新浏览器使 Custom Elements 重新注册；安装目录版本正确不能代替实际加载核验。几何数值在 input 时保存，预览响应必须同时匹配请求序列及当前几何签名，防止旧响应覆盖连续编辑或未失焦输入。

普通运行页恢复旧版参数与日志并排组织，显示后端当前状态和尝试号，不出现恢复操作说明。取消由宿主授权执行；复用参数产生新配置，不自动重跑旧任务。工作台保持直接校验创建，智能体仅在最终原生 ASK 中审阅执行。

计算阶段读取同一次尝试的 `runtime.current_stage/current_stage_status/current_model_time/model_progress`。WRF 模拟百分比来自已观测模型时间；WPS 或未观测到时间时只显示阶段文字，不用固定流程百分比代替计算进度。下载、渲染和终态使用实际任务阶段。

结果组件按域、变量和时次播放，读取后端 WebP、真实 extent 和 palette；只有通过 EPSG:3857 重投影校验的产品才精确叠加。旧产品缺定位时显示原图及原因，不伪造地理定位。资源经 Bearer 获取 Blob，切换请求中止旧读取，卸载释放 URL；部分产品保留质量提示。
