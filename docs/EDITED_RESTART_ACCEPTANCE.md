# 修改参数后一次点击重跑

2026-10-15，主站前端热更新已核验。

修改任务后点击“修改后重跑”，前端直接沿既有接口读取原任务、检查尝试编号、制定manual restart计划并执行，不再打开第二次确认弹窗。提交中禁用表单并显示“正在提交重跑…”。后端原权限、计算终态、身份、引用、路径、配置复核和尝试锁均保留；智能体ASK和其他操作的确认流程未改。

执行前按账户、任务和原attempt持久保存原计划编号。响应丢失后刷新只查询原计划；accepted恢复原任务显示，pending/executing/unknown不重复执行。账户变化使旧响应失效。没有新增接口、数据库表或部署职责，仅增加现有GET计划接口的前端封装。

重跑继续使用既有后端归档：`runs/<task>/attempts/NNN/service.log`保存旧日志，`attempt.json`保存旧request/runtime/failure/error/status，独立尝试记录保存日志路径。现代不可变远端attempt目录及其WRF/WPS日志保留，下一次使用新attempt目录。运行页“第N次”按钮读取旧日志和旧参数。未改写或删除真实失败日志，也没有替用户重跑截图中的任务。

验证：33项后端安全/手动操作回归通过，新增用例证明20层失败日志及failure/request归档、修改为88层后旧日志仍可按attempt_no=1读取；已有同attempt并发重跑只清理一次、未知身份阻断等保护通过。

6项隔离浏览器通过：无弹窗直接执行；响应丢失后刷新恢复accepted且不新增计划/执行；unknown刷新后保留原编号并拒绝重复执行；旧日志历史选择；其他结果处理/连接/部分渲染入口行为保持。全部计算/恢复请求由夹具拦截，无实际业务重算。最终前端构建通过，原Rollup注释和bundle大小提示保留。
